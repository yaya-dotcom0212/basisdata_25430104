## 2. Ringkasan Dasar Teori

A. MariaDB and the CLI (Command Line Interface)

MariaDB adalah sistem manajemen basis data relasional (Relational Database Management System / RDBMS) berbasis SQL (Structured Query Language). Penggunaan CLI melalui Terminal atau Command Prompt XAMPP memberi akses langsung ke mesin MariaDB tanpa perantara GUI. Ini penting untuk memahami sintaks asli SQL, memudahkan otomatisasi skrip, dan membiasakan diri dengan lingkungan server produksi.

### B. Keamanan Basis Data dan Hak Akses (Least Privilege)

Dalam administrasi basis data, berlaku prinsip *Principle of Least Privilege*. Prinsip ini berarti memberikan hak akses sekecil mungkin sesuai kebutuhan peran pengguna.

* **Akun `root`:** Memiliki hak tertinggi sebagai Superuser. Akun ini hanya dipakai untuk tugas administrasi sistem.

* **Akun Aplikasi/Pengguna:** Hanya mendapat hak akses terbatas pada basis data tertentu saja.
* Perintah utama mencakup:

* `CREATE USER`: Membuat akun baru.

* `GRANT`: Memberi hak akses tertentu, seperti `SELECT`, `INSERT`, atau `ALL PRIVILEGES` .

* `FLUSH PRIVILEGES`: Memuat ulang tabel hak akses ke memori server.

### C. Kontrol Versi dengan Git

Git adalah sistem kontrol versi yang banyak digunakan dalam pengembangan perangkat lunak. Dengan Git, kita bisa melacak perubahan kode, bekerja sama dengan tim, dan mengelola beberapa versi dari satu proyek dengan mudah. Git menyimpan riwayat perubahan sehingga memudahkan kita untuk kembali ke versi sebelumnya jika terjadi kesalahan. Selain itu, Git mendukung kerja tim dengan fitur seperti branch dan merge. Fitur branch memungkinkan kita membuat cabang pengembangan tanpa mengganggu kode utama. Setelah selesai, kita bisa menggabungkan hasil kerja ke kode utama menggunakan merge. Git juga terintegrasi dengan layanan seperti GitHub, GitLab, dan Bitbucket yang memudahkan kolaborasi secara online.

Git digunakan untuk melacak riwayat perubahan pada berkas skrip basis data (`.sql`) dan dokumentasi (`.md`)[cite: 37]. Berkas `.gitignore` dipakai untuk mengecualikan berkas sensitif, seperti berkas kredensial, `.env`, atau log lokal. Tujuannya agar berkas-berkas tersebut tidak ikut terunggah ke repositori publik dan kerahasiaan data tetap terjaga.

# 4. Jawaban Titik Analisis

1. **Mengapa kita perlu memakai CLI dibanding GUI seperti phpMyAdmin atau DBeaver saat belajar dasar basis data?**

* **Jawaban:** Menggunakan CLI membantu memahami sintaks SQL murni tanpa bergantung pada antarmuka visual. Selain itu, penggunaan CLI sangat penting untuk otomatisasi skrip di lingkungan server produksi seperti deployment atau CI-CD. Biasanya, lingkungan ini tidak menyediakan GUI.

2. **Mengapa aplikasi web atau pengguna umum tidak boleh langsung memakai akun `root`?**

* **Jawaban:** Akun `root` punya hak akses tertinggi (*superuser*) untuk semua basis data dan pengaturan server[cite: 36]. Jika aplikasi terhubung dengan akun `root` lalu terjadi kerentanan seperti *SQL Injection*, peretas bisa mengambil alih seluruh sistem basis data. Mereka bisa menghapus atau mencuri data sensitif dari basis data lain.

3. **Mengapa berkas yang berisi kata sandi atau kredensial harus dimasukkan ke dalam `.gitignore`?**

Berkas yang menyimpan kata sandi atau kredensial bisa membahayakan keamanan jika ikut masuk ke dalam sistem kontrol versi seperti Git. Jika berkas ini tidak dimasukkan ke `.gitignore`, isi berkas bisa saja terbuka untuk semua orang yang punya akses ke repositori. Hal ini bisa menyebabkan kebocoran informasi penting, seperti akses ke database atau layanan pihak ketiga. Dengan memasukkan berkas ini ke `.gitignore`, kita mencegah informasi sensitif tersebut ikut terunggah ke repositori.

* **Jawaban:** Untuk mencegah kebocoran data sensitif seperti credential leakage. Jika berkas kredensial terunggah ke repositori remote seperti GitHub atau GitLab, kredensial tersebut bisa dilihat oleh publik atau pihak yang tidak berwenang. Hal ini berisiko tinggi memicu peretasan sistem.

### B. Pembuatan Skrip Idempoten 

Skrip diubah supaya bisa dijalankan beberapa kali tanpa menimbulkan kesalahan jika basis data atau pengguna sudah ada.

### D. Isi Berkas `.gitignore`

Berkas `.gitignore` berisi daftar pola nama file dan folder yang harus diabaikan oleh Git. Ini penting agar file sementara, file build, atau file pribadi tidak ikut masuk ke dalam sistem versi. Anda bisa menulis satu pola di setiap baris. Misalnya, `*.log` akan mengabaikan semua file dengan ekstensi `.log`. Gunakan tanda `#` untuk menulis komentar. Jika ingin mengecualikan folder, tambahkan garis miring di akhir, seperti `temp/`. Jika sebuah file atau folder sudah terlanjur masuk ke repository, Anda harus menghapusnya dari repository terlebih dahulu agar aturan `.gitignore` berlaku.

```text

# Mengabaikan berkas kredensial & environment

*.env

kredensial*.txt

# Mengabaikan log lokal dan folder IDE

*.log

.vscode/

.idea/

```

### Kendala dan Solusi

1. **Kendala:** Saat menjalankan perintah SQL pada CLI, muncul pesan galat sintaks (syntax error). Hal ini terjadi karena lupa menambahkan tanda titik koma (`;`) di akhir baris[cite: 36].

* **Solusi:** Biasakan untuk memeriksa kembali dan selalu mengakhiri setiap instruksi SQL dengan tanda `;` sebelum menekan `Enter`.

2. **Kendala:** Kesalahan muncul saat menjalankan ulang skrip SQL. Basis data `kopma_123` sudah dibuat sebelumnya.

* **Solusi:** Perbaiki skrip agar bersifat *idempotent* dengan menambah klausa `IF NOT EXISTS`.

3. **Kendala:** Salah menulis nama cabang default Git saat *commit* pertama.

* **Solusi:** Jalankan perintah `git branch -M main` untuk memastikan cabang utama memakai nama `main` sesuai standar repositori.
